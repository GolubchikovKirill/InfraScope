# Аудит модуля удалённого доступа (RustDesk) — 03.09.2026

Проверено на живом проде: InfraScope-модуль `app/domains/remote_access`,
отдельный стек `~/rustdesk` (hbbs/hbbr/api), реальный парк из 133
управляемых устройств. Всё ниже — не гипотезы, а то, что подтверждено
командой/логом/запросом. Исполнитель работ — Sonnet 5.

Состояние на момент аудита: 35 машин `configured`, 16 `pending`,
82 `unknown` (в основном кассы, которые ещё не разворачивали), общая книга
адресов — 133 строки, все с паролями, фоновая синхронизация здорова
(каждые 2 мин, ~0.5 с, `console_error: None`).

## 0. Три машины, где упал WMF 5.1 — причины разные

Диагностировано по `C:\Windows\Logs\CBS\CBS.log` и состоянию машин.
Общего корня нет, каждой нужен свой шаг. Перезагрузки делает пользователь.

| Машина | Код | Причина (проверено) | Что делать |
|---|---|---|---|
| VNA-MUZ-901 | `0x8000FFFF` | **Нет .NET Framework 4.x вообще** — в `C:\Windows\Microsoft.NET\Framework` только до `v3.5`. WMF 5.1 жёстко требует .NET 4.5.2+. Дополнительно нет `KB4474419` (SHA-2) и отстаёт servicing stack (4 записи `KB3177467` против 8 у соседей) | Порядок: SSU → `KB4474419` → .NET 4.8 (офлайн-инсталлятор) → WMF 5.1 |
| VNA-MGR-2701 | `0x800F0900` | CBS: `Mark store corruption flag because of package: Package_for_KB4036586_RTM~…~amd64~~11.2.1.0` — манифест `.mum` не парсится (невалидный XML). **Хранилище компонентов помечено повреждённым** | System Update Readiness Tool (CheckSUR, `KB947821`) для Win7 x64; либо подменить конкретные `.mum`/`.cat` с исправной идентичной машины. Затем повтор WMF |
| VNA-MGR-1602 | `0x80092004` | Пакет цел (SHA256 совпал с источником), .NET 4.7 есть, `KB4474419` есть, `CryptSvc` работает — но в `C:\Windows\System32\catroot2` всего **11 файлов**: база каталогов подписей пуста/повреждена, отсюда `CRYPT_E_NOT_FOUND` | Остановить `CryptSvc`, переименовать `catroot2` → `catroot2.old`, запустить `CryptSvc` (пересоздаст), повтор WMF |

Важно: `wusa` на этих машинах ничего не ломает — все три упали до внесения
изменений. Ретраи без устранения причины бессмысленны (проверено: VNA-MUZ-901
дважды упала с одинаковым кодом).

## 1. Безопасность

### CRIT-1. Deploy-токен даёт пароли всего парка

**Проверено end-to-end.** Цепочка:

1. На ~40 машинах после раскатки остался `C:\ProgramData\InfraScope\bootstrap-trigger.ps1`
   с токеном в открытом виде. ACL — `BUILTIN\Пользователи` (обычный кассир читает).
2. `POST /api/v1/remote-access/deploy/config` с этим токеном и **любым**
   managed-hostname возвращает `permanent_password` этой машины
   (проверено запросом для чужого хоста — пароль пришёл).
3. `desired_unattended = true` по всему парку → пароль это и есть полный
   неинтерактивный доступ.

Итого: с любой развёрнутой машины из-под обычного пользователя берётся
контроль над всем парком. Единый пароль `kentdful` увеличивает ущерб.

Что делать:
- **Немедленно (Sonnet, шаг 1):** снести `bootstrap-trigger.ps1` со всех машин,
  где он остался; ротировать `RUSTDESK_DEPLOY_TOKEN`.
- **Структурно:** в `deploy_config` сверять источник запроса с запрашиваемым
  хостом — роут уже логирует `request.client.host`, но не проверяет его
  (`app/api/routes/remote_access.py`). Одного этого хватает, чтобы убить
  сбор чужих паролей.
- Одноразовые короткоживущие тикеты на устройство вместо вечного
  общего токена (`mark_deploy_requested` — естественное место, чтобы их выдавать).
- Уникальный пароль на машину вместо общего (`rotate_password` уже есть;
  `RUSTDESK_DEFAULT_PASSWORD` оставить только как fallback).

### CRIT-2. Bootstrap доверяет любому TLS-сертификату

`deploy_script.deploy_command()` ставит
`ServerCertificateValidationCallback = {$true}` — проверка сертификата
отключена целиком. Любой, кто может выдать себя за `10.10.99.24`, выполнит
произвольный PowerShell **как SYSTEM** на каждом endpoint'е парка.

Фикс: пиннинг отпечатка сертификата вместо безусловного доверия (сравнивать
`$_.GetCertHashString()` с зашитым значением), либо положить корневой
сертификат в доверенные на машинах.

### HIGH-1. Консоль работает по открытому HTTP

`api-server = http://10.10.99.24:21114` (и в `~/rustdesk/conf/config.yaml`,
и в конфиге, который раскатывается на машины). По LAN открытым текстом ходят
логины инженеров и **вся общая книга с паролями всех машин**.

Фикс: терминировать TLS перед 21114 (nginx во фронтенд-контейнере уже
терминирует 443), поменять `api-server` в конфиге раскатки, выставить
`trust-proxy` в `config.yaml`.

### HIGH-2. Токены консоли живут 10 лет, брутфорс не ограничен

Из `conf/config.yaml`: `token-expire: 87600h`, `jwt.expire-duration: 87600h`
(≈10 лет), `ban-threshold: 0` (блокировка после N неудач **выключена**),
`web-client: 1` (веб-клиент включён). Токен, вытащенный из конфига клиента
на любой машине, практически бессрочен.

Фикс: разумный срок жизни токена, включить `ban-threshold`, оценить, нужен ли
веб-клиент.

### MED-1. Приватный ключ сервера читается всеми

`~/rustdesk/data/server/id_ed25519` — режим `644`. Должен быть `600`.

### MED-2. Инженерные учётки — админы консоли

`golubchikovka` заведена с `is_admin = True`. Для работы достаточно членства
в группе `InfraScope Admins` с read-only правилом на книгу (правило уже
такое: `type=2, to_id=3, rule=1`). Пересмотреть `create_console_user`.

## 2. Надёжность и эксплуатация

### HIGH-3. У RustDesk-стека нет бэкапа

`~/rustdesk/data` — 1.5 МБ, и в них: `id_ed25519` (**потеря = перенастройка
всех ~150 машин**, потому что ключ зашит в конфиг каждого клиента), реестр
пиров, учётки консоли и общая книга адресов с паролями. Cron-задач нет,
в `~/backups` ничего по rustdesk.

Фикс: ежедневный `tar` с ротацией, желательно off-host. Восстановление
проверить на практике.

### HIGH-4. Образы прибиты к `:latest`

`lejianwen/rustdesk-server:latest`, `lejianwen/rustdesk-api:latest`.
Любой `pull`/пересоздание может молча увести на несовместимую версию, а от
этих контейнеров зависит связность всего парка. С учётом того, что
Docker Hub с этого сервера тянется нестабильно, это ещё и риск не подняться
обратно.

Фикс: пин на конкретный тег и дайджест.

### MED-3. Ни одного healthcheck

У `hbbs`/`hbbr`/`api` нет `healthcheck`. Зависший, но живой процесс никто не
заметит: InfraScope увидит только отказ API-вызовов. Prometheus в стеке уже
есть — довести до алерта.

### MED-4. Книга адресов не сверяется с реальностью

`sync_stale_address_book` отбирает устройства **только по флагам в БД**
(`in_address_book`, `ab_password_pushed`) и никогда не сравнивает с тем, что
реально лежит в консоли. Если строка исчезла в консоли — устройство выпадает
из книги навсегда, а интерфейс продолжает показывать «в книге».

Это не теория: сегодня при чистке дублей 28 машин выпали из книги ровно так,
и InfraScope этого не заметил (восстановлено вручную, книга снова 133/133).

Причина выпадения — **баг в `delete_device`**: он удаляет строку в консоли по
`ab_row_id`, не проверяя, что на тот же `rustdesk_id` ссылается другая живая
запись (у дубля по регистру `rustdesk_id` совпадал с оригиналом, строка в
консоли была общая).

Фикс: (а) в `delete_device` не трогать строку консоли, если на тот же
`rustdesk_id` есть другое устройство; (б) периодическая сверка списка
консоли с БД, расхождение — в метрику и баннер на странице.

### MED-5. Удаление устройства не держится

`seed_from_inventory` в beat-задаче (каждые 2 минуты) пересоздаёт запись,
если инвентарная строка жива. Проверено на `HPI2E8F25`: удалена — вернулась
через минуту, уже с новым паролем и сброшенным статусом.

Фикс: мягкое удаление — `managed = False` + исключение из выдачи списка
(поле уже документировано как «unset to stop InfraScope from tracking it»,
но `list_devices` его не фильтрует, а `ensure_device` безусловно ставит
`True`), либо отдельная таблица исключений по hostname.

### MED-6. В модуль затягивается лишнее из инвентаря

`macbook-pro` (ноутбук, подключившийся по VPN) оказался управляемым
устройством: сетевое обнаружение заводит `Computer` на любой найденный хост,
а `seed_from_inventory` зеркалит все `Computer` подряд.

Фикс: сузить источник (только доменные машины / из AD) либо явный признак
«берём под управление».

## 3. Производительность и качество

### LOW-1. Регистронезависимый поиск не индексирован

Сегодняшний фикс дублей перевёл поиск на `lower(hostname)` — `EXPLAIN`
показывает `Seq Scan` (индекс `ix_remoteaccessdevice_hostname`
регистрозависимый и больше не используется). На 133 строках это 0.2 мс, но
это ~150 запросов каждые 2 минуты и деградация с ростом парка. Плюс на уровне
БД дубли по регистру всё ещё возможны — уникальность регистрозависимая.

Фикс: миграция с функциональным уникальным индексом
`CREATE UNIQUE INDEX … ON remoteaccessdevice (lower(hostname))` — закрывает
и производительность, и инвариант.

### LOW-2. N+1 в `sync_from_console`

На каждого пира — `_get_or_create_device` (1 SELECT) + `_link_inventory`
(до 3 SELECT). При 39 пирах это ~150 запросов каждые 2 минуты.
Фикс: предзагрузить карты `hostname → device` и `hostname → inventory`
одним запросом на прогон.

### LOW-3. Нет rate limit на `/deploy/*`

`slowapi` в проекте настроен (`app/core/limiter.py`), но на эти роуты не
навешан.

## 4. Что работает хорошо — не ломать

- **Pull-модель без remote execution.** Подтверждена на практике: Kaspersky
  сегодня блокировал именно повторные удалённые запуски (процесс висел с
  0.02 с CPU), тогда как штатный pull-путь у AV вопросов не вызывает.
- Отчёты endpoint'а хранятся verbatim, состояние не додумывается.
- Деградация при недоступной консоли: sync не падает целиком, на странице
  честный баннер.
- Пароли шифруются в БД (Fernet, недетерминированно).
- 303 unit-теста, quality gate работает; сегодняшние правки (регистр,
  гонка пароля, 404) закрыты тестами.

## 5. План работ (по приоритету)

Каждый пункт: правка → тест → прогон `tests/unit` в test-builder → деплой
(см. `CLAUDE.md`). Пункты внутри фазы независимы.

### Фаза 1 — закрыть дыру с токеном (в первую очередь)

1. **Убрать оставленные скрипты.** Пройтись по машинам, где после раскатки
   остался `C:\ProgramData\InfraScope\bootstrap-trigger.ps1`, и удалить его.
   Список машин — из `remoteaccessdevice` со статусом `configured`.
2. **Проверка источника в `deploy_config`** (`app/api/routes/remote_access.py`):
   отдавать конфиг только если запрос пришёл с адреса, который резолвится в
   запрашиваемый hostname (или совпадает с `last_ip` устройства). Поведение
   при несовпадении — 404 плюс warning в лог. Тесты: свой хост — ок; чужой
   хост с валидным токеном — 404.
3. **Ротация `RUSTDESK_DEPLOY_TOKEN`** в `.env` на сервере после п.1–2.
4. **Пиннинг сертификата в bootstrap** (`deploy_script.deploy_command`):
   вместо `{$true}` сравнивать отпечаток. Тест на присутствие отпечатка и
   отсутствие безусловного `$true`.

### Фаза 2 — целостность данных

5. **`delete_device`: не удалять общую строку консоли**, если на тот же
   `rustdesk_id` ссылается другое устройство. Тест на пару «дубль + оригинал».
6. **Мягкое удаление вместо жёсткого**: `managed = False` + фильтр в
   `list_devices` (и в `seed_from_inventory` не поднимать обратно).
   Тест: удалили → прогнали seed → устройство не вернулось.
7. **Сверка книги с консолью**: в `sync_stale_address_book` (или отдельным
   шагом beat-задачи) считать расхождение «есть в БД / нет в консоли»,
   чинить пуш и отдавать число в `address_book_status` для баннера.
   Тест: строка пропала в консоли → следующий прогон её восстановил.
8. **Функциональный уникальный индекс по `lower(hostname)`** — миграция
   Alembic. Перед созданием убедиться, что дублей нет (сейчас их нет).

### Фаза 3 — стек RustDesk

9. **Пин образов** на конкретный тег+дайджест в `~/rustdesk/docker-compose.yml`.
10. **Бэкап `~/rustdesk/data`**: ежедневный tar с ротацией + разовая проверка
    восстановления. Хранить рядом с существующими `~/backups`.
11. **`chmod 600` на `id_ed25519`.**
12. **Healthcheck'и** для `hbbs`/`hbbr`/`api` + алерт в Prometheus.
13. **TLS перед 21114** и правка `api-server` в конфиге раскатки (это меняет
    конфиг на всех машинах — планировать вместе с очередной волной раскатки).
14. **Сроки жизни токенов и `ban-threshold`** в `conf/config.yaml`.

### Фаза 4 — гигиена модуля

15. **Сузить `seed_from_inventory`**, чтобы в модуль не попадали случайные

16. **Убрать N+1** в `sync_from_console`.

18. **Наименьшие привилегии** для инженерных учёток консоли (`is_admin=False`).
