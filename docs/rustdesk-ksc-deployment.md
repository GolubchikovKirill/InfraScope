# RustDesk на парк — через Kaspersky Security Center

InfraScope **не ставит** клиент RustDesk. Раскатка идёт штатным механизмом KSC:
преднастроенный пакет + post-install скрипт [`rustdesk-ksc/configure.ps1`](../rustdesk-ksc/configure.ps1).
InfraScope отвечает за учёт, статусы, книгу адресов и хранит желаемый конфиг
каждой машины.

Почему не агентом из приложения: удалённый запуск с Linux-сервера (`impacket`/`wmiexec`)
неотличим от lateral movement и блокируется самим Касперским. KSC — родной путь.

---

## Что кладём в пакет KSC

1. Официальный инсталлятор `rustdesk-<версия>-x86_64.exe` (версия — из
   `RUSTDESK_INSTALLER_VERSION`, сейчас `1.4.9`). Скачивается с
   `github.com/rustdesk/rustdesk/releases`.
2. `configure.ps1` (из `rustdesk-ksc/`).
3. `rustdesk-ksc.json` — конфиг. Скопировать из `rustdesk-ksc.example.json` и
   заполнить:
   - `id_server` / `relay_server` — `10.10.99.24`
   - `api_server` — `http://10.10.99.24:21114`
   - `key` — публичный ключ hbbs (`~/rustdesk/data/id_ed25519.pub` на сервере)
   - `permanent_password` — общий пароль пакета (например `kentdful`), либо пусто
     если ставите per-machine (см. ниже)
   - `hidden` / `block_outgoing` / `unattended` — `true`

Один пакет = один пароль. Нужны разные пароли по классам (кассы / ПК / неттопы) —
сделайте 3 пакета с разными `rustdesk-ksc.json`.

### Per-machine ID и пароль

InfraScope хранит желаемый `rustdesk_id` (по hostname) и пароль на устройство.
`configure.ps1` без `rustdesk_id` в конфиге сам выведет ID из имени машины
(`VNK-MGR-01` → `VNK_MGR_01`) — этого достаточно, ID и так уникален.

Забрать точный конфиг одной машины:
```
GET /api/v1/remote-access/devices/{id}/package
```
отдаёт ровно те ключи, что читает `configure.ps1`.

## Настройка в KSC

**Администрирование → Хранилища → Инсталляционные пакеты → Создать**

1. **Тип:** «Создать инсталляционный пакет для программы, указанной пользователем».
2. **Файл:** `rustdesk-1.4.9-x86_64.exe`.
3. **Параметры запуска установки:** `--silent-install`
4. **Дополнительные файлы пакета:** добавить `configure.ps1` и `rustdesk-ksc.json`.
5. **Действие после установки** (вкладка «Настроить» → «Запускать после установки»
   или через задачу-скрипт):
   ```
   powershell.exe -NoProfile -ExecutionPolicy Bypass -File "configure.ps1"
   ```
   Скрипт запускается от `SYSTEM` — прав хватает на конфиг, сервис, ярлыки,
   AppLocker.

**Задача «Удалённая установка программы»:**
- Выбрать созданный пакет.
- Область действия: нужная группа администрируемых устройств. **Кассы —
  отдельной задачей / расписанием**, не в бизнес-часы.
- Способ доставки: через Агент администрирования (стандартный).
- Расписание: вручную либо «по мере обнаружения новых устройств».

## Проверка после раскатки

На машине: `C:\ProgramData\InfraScope\rustdesk-configure.log` — там строки
`server + id written`, `password set + verified` (или `WARN` если пароль не
записался — тогда добить вручную: `"C:\Program Files\RustDesk\rustdesk.exe" --password <pw>`
в **elevated interactive**).

В InfraScope: страница «Удалённый доступ» → устройство перейдёт в онлайн по
консоли RustDesk (колонка «RustDesk»), подтянется версия и залогиненный
пользователь. Кнопкой «Синхронизировать книгу адресов» протолкнуть записи в
консоль, чтобы техники видели парк в клиенте.

## Ротация пароля

1. В InfraScope на карточке устройства «Ротировать пароль» — генерит новый,
   помечает `password_rotated_at`.
2. Обновить `rustdesk-ksc.json` в пакете (или собрать per-class пакеты заново).
3. Перезапустить задачу KSC на нужную область — `configure.ps1` идемпотентен,
   переприменит только пароль/конфиг, переустановку не делает.
